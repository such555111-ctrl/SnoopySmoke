# SH SHOP — Telegram Mini App

Витрина **SH SHOP** («Всё для пара», «Лучшие цены») в виде Telegram-бота с мини-приложением:
каталог, избранное, корзина, промокоды, оформление заказа, профиль с историей заказов и админ-панель.
Заказ уходит менеджеру (@SHvape_manager), онлайн-оплата не подключена.

## Состав
```
main.py           — Flask-сервер (все данные — в Neon): мини-апп, Telegram-бот (webhook), API админки
index.html        — интерфейс мини-приложения (18+ гейт, hero, каталог, корзина, заказ)
admin.html        — админ-панель (товары, заказы, вопросы, промокоды)
products.json     — каталог SH SHOP (82 позиции из прайса канала)
brand/            — sh-logo.png, sh-avatar.png (512×512), sh-banner.png (1280×640) и анимированные *-animated.svg (открывать в браузере)
requirements.txt, Procfile, render.yaml — запуск на Render
```

Логотип вшит как SVG-спрайт `#sh-logo`; файлы для аватарки бота/канала — в `brand/`.

## Запуск (Render)
1. @BotFather → `/newbot`, затем `/setuserpic` → `brand/sh-avatar.png`.
2. Загрузите файлы в корень GitHub-репозитория, на Render создайте Web Service.
   Build: `pip install -r requirements.txt`, Start: `gunicorn main:app --bind 0.0.0.0:$PORT`.
3. Переменные окружения: `BOT_TOKEN`, `ADMIN_PASSWORD`, `ADMIN_CHAT_ID` (ваш Telegram ID, можно несколько через запятую),
   `SHOP_CONTACT` (по умолчанию `SHvape_manager`), `WEBHOOK_URL` (необязательно),
   `DELIVERY_FEE` (стоимость доставки, по умолчанию `200`), `PICKUP_POINTS` (пункты самовывоза через запятую, по умолчанию `Пролетарская,Девяткино,Мурино`).
4. `/start` в боте → «🚀 Открыть SH SHOP». Админка: `https://ваш-адрес.onrender.com/admin`.

## Что заполнить после запуска
- Фото товаров, реальные вкусы/цвета и описания — через `/admin` (сейчас у позиций «Вкус / цвет — по согласованию» и цветные плашки).
- Бейджи («Хит», «Скидка» и т.д.) — в админке; сейчас «Хит» только у жидкости «Монашка».
- Номера заказов имеют вид `SH-12`.

> Проверьте требования законодательства вашего региона к продаже и дистанционной торговле никотиносодержащей продукцией.

## Хранение данных (Neon)
Всё хранится в PostgreSQL на Neon — рестарты и деплои на Render ничего не стирают, Persistent Disk не нужен:

| Таблица | Что лежит |
| --- | --- |
| `products` | товары (включая остатки, бейджи, ссылки на фото) |
| `orders` | заказы и переписка с покупателем |
| `questions` | вопросы по товарам |
| `promos` | промокоды и счётчики использования |
| `reviews` | отзывы и их модерация |
| `images` | фото товаров (загружаются через админку, сжимаются до 1600 px WebP, отдаются по `/uploads/<имя>`) |
| `meta` | служебный флаг первичного переноса |

Нужна одна переменная `DATABASE_URL` (строка подключения Neon, с `?sslmode=require`). Таблицы создаются автоматически.
При первом запуске пустая база заполняется из `products.json` (и `orders.json`, `questions.json`, `promos.json`,
папки `uploads/`, если они есть) — один раз; дальше источник правды — база, а `products.json` в репозитории можно не трогать.
Фото, которые больше не привязаны ни к одному товару, удаляются из базы автоматически.

## Анимации
- Логотип: плавает, блик скользит по буквам, дым дрейфует, молнии мерцают, искры и угли поднимаются, корона покачивается.
- Интерфейс: дым на фоне, вращающаяся подсветка рамки hero, бегущая градиентная лента, блики на кнопках и карточках, пульсация «Хита».
- Для пользователей с включённым «уменьшить движение» в системе все анимации отключаются автоматически.

## Заказ: самовывоз / доставка / время
При оформлении покупатель выбирает **самовывоз** (один из пунктов) или **доставку** (вводит адрес, +`DELIVERY_FEE` ₽ к итогу),
а также «как можно скорее» или конкретные дату и время. Эти данные приходят администраторам и покупателю в Telegram,
видны в админке (вкладка «Заказы») и в истории заказов покупателя.

## Подкатегории
У товара есть необязательное поле `subcategory` (бренд): например `Поды › Vaporesso › Xros 6`.
В каталоге под категориями появляется вторая строка фильтров с количеством товаров; товары без подкатегории
попадают в «Другие». Поле заполняется в админке («Подкатегория / бренд»), подсказки берутся из уже созданных.

## Остатки товара
В админке (карточка товара → «Остаток на складе, шт.») и прямо в списке товаров (кнопки «−» / «+» и поле ввода) можно указывать количество.
- Пусто — учёт не ведётся, товар без ограничений (так по умолчанию).
- В каталоге у карточки появляется плашка: «В наличии: N шт.» (больше 10), «Осталось N шт.» (4–10), «Последние N шт.» / «Остался 1 шт.» (1–3), «Нет в наличии» (0).
  Распроданные товары уходят в конец ленты, блёкнут, их нельзя добавить в корзину.
- В карточке товара — шкала остатка; в корзину нельзя положить больше, чем есть на складе.
- При оформлении заказа сервер проверяет остатки и списывает их; отмена заказа (клиентом или в админке) возвращает товар на склад,
  возобновление отменённого заказа списывает снова. Остатки в мини-приложении обновляются при возврате в приложение и после заказа.
- Остатки хранятся в таблице `products` (поле `stock`) в Neon и переживают рестарты.

## Каталог списком, боковое меню и быстрый заказ
- **Список вместо сетки.** Каждая позиция — компактная строка: квадратная миниатюра слева; название, бренд (подкатегория),
  артикул (поле `sku`/`article`/`code` в `products.json`, если заполнено), цена «180,00 ₽/шт» и остаток «В наличии: N шт.» по центру;
  квадратная кнопка `+` справа. Строка остатка показывается, если у товара задан `stock` (в админке).
- **Быстрый заказ в 1 клик.** `+` кладёт 1 шт. в корзину без открытия карточки: вибрация (Telegram Haptic / `navigator.vibrate`),
  всплывающее «+1», счётчик на кнопке и в шапке. Лимит остатка соблюдается. При `stock = 0` кнопка серая «Нет» и заблокирована.
  Если у товара несколько вариантов (`sizes` больше одного), `+` откроет карточку для выбора.
- **Боковое меню категорий** (бургер слева в шапке): «Все товары», «Всё для вейпа», «Жевательный табак»,
  «Импортные сигареты / сигариллы», «РАСПРОДАЖА». Соответствие пунктов категориям из `products.json` задаётся в `index.html`
  в константе `MENU_MAP` (в конце скрипта). РАСПРОДАЖА показывает товары с бейджем «Скидка» или `old_price` больше `price`.
- Выбранная категория показывается бейджем над списком (кнопка «Все товары» сбрасывает). Поиск работает внутри выбранной категории.

## Отзывы с модерацией в Telegram

Покупатель оставляет отзыв в мини-аппе («⭐ Отзывы» в шапке или меню). Отзыв сохраняется как неодобренный,
а админам (`ADMIN_CHAT_ID`) бот присылает сообщение с кнопками **✅ Одобрить** / **❌ Отклонить**:

- «Одобрить» — отзыв получает `is_approved = True` и появляется в магазине;
- «Отклонить» — запись удаляется из базы.

Кнопки работают только у пользователей из `ADMIN_CHAT_ID`. Повторное нажатие или нажатие у второго админа
покажет «Этот отзыв уже обработан».

API: `GET /api/reviews` (только одобренные + средний рейтинг и количество), `POST /api/reviews`.

**База данных.** Отзывы лежат в SQL-базе (SQLAlchemy). Задайте переменную окружения `DATABASE_URL`
(строка подключения Neon PostgreSQL). Без неё используется локальный SQLite-файл `shop.db`,
который на бесплатном Render стирается при каждом деплое — для продакшена `DATABASE_URL` обязателен.

В админ-панели есть вкладка **«Отзывы»**: все отзывы (опубликованные и на модерации) с кнопкой «Удалить».

## Баллы и кешбэк
**1 балл = 0,5 ₽.** Таблица `loyalty_users` (`telegram_id` — уникальный, `points_balance`, `total_spent`).
- `GET /api/loyalty/balance?telegram_id=…` → `{telegram_id, points_balance}`; нет записи — создаётся с балансом 0.
- `POST /api/order` (он же `/api/orders`) принимает `points_to_spend` — целое число баллов, не больше баланса.
  Скидка в рублях = `points × 0,5` и не может превышать `MAX_POINTS_PERCENT` (30%) суммы товаров после промокода
  (доставка баллами не оплачивается), то есть максимум `сумма × 30% / 0,5` баллов.
- Кешбэк начисляется баллами: `round((сумма_рублями × 5%) / 0,5)`, где сумма_рублями — итог к оплате деньгами
  после скидки баллами (с доставкой), округление «half up».
- Отмена заказа (клиентом или в админке) возвращает списанные баллы и забирает начисленный кешбэк;
  возобновление отменённого заказа применяет их снова.
- В заказе сохраняются `points_spent`, `points_discount` (₽), `cashback` (баллы), `goods_total`; админу уходит строка
  «Оплачено баллами: ХХ б. (ХХ ₽) | Начислено кешбэка: ХХ б. (ХХ ₽)».
- Настройки через переменные окружения: `POINT_VALUE_RUB` (0.5), `CASHBACK_PERCENT` (5), `MAX_POINTS_PERCENT` (30).
